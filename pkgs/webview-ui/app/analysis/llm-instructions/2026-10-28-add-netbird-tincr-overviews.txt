# Template
Use `nebula_overview.md` in the analysis dir as the structural template: same
`#`/`##`/`###` headings in the same order (Overview, Protocol, Encryption,
Performance, Security, NAT Traversal, Local Routing, Central Point of Failure,
Authentication, Platform Support) and the same checklist items with their bold
names. Prose style: plain, factual, no source links inside the doc (evidence
goes in the report). Checklist convention: `- [x] **Item** - ...` for yes,
`- [x] **Item** - Partial: ...` for partial/opt-in, `- [ ] **Item** - ...` for
no, and say "N/A" in the text when it does not apply. Performance claims are
judged on Linux with the default build, since that is what the benchmark runs.
Cover threading, batching (recvmmsg/sendmmsg), UDP GSO/GRO, TUN offload, socket
buffers, MTU and default peer transport carefully.

# Contract
Matrix row definitions + legend: `matrix-contract.md`. Use them exactly.
Additional rules decided after that file was written:
- Extra row "Datagram encapsulation (no head-of-line blocking)": ✓ if on the
  default path each inner packet is an independent datagram, ✗ if carried in a
  reliable ordered stream (TCP, QUIC stream, TLS), ◐ if it depends on an opt-in
  transport.
- Extra glance key "Default peer transport": what a fresh 2-node Linux setup
  uses for data, plus the fallback.
- Controller rows (Controller redundancy, Cached credentials, Certificate
  pinning = control-server key pinning) are N/A when the design has no
  controller.
- Linux-only syscalls count as ✓ if used on Linux by default.

# Report
Write `verify-<VpnName>.md` with sections `## Glance` (table: Key | Value |
Evidence, contract section A plus "Default peer transport"), `## Matrix` (table:
Row | Value | Evidence; one row per contract row in sections B and C plus the
Datagram encapsulation row, using the exact row names from the contract),
`## Caveats` (3-6 bullets: most important security/performance problems a ✓/✗
grid cannot show), `## Row critique`. Every value needs `repo/path:LINE`
evidence.

Final reply: 5-10 line summary plus the doc and report paths. No builds, tests
or network installs.
